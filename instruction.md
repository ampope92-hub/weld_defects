We do robotic welding for structural fabricators and every joint gets an ultrasonic inspection afterwards, which is slow and expensive. I want to flag the joints worth inspecting straight off the process data. `/app/data/train.csv` is nine thousand welds where the inspector recorded what they found — `defect` is `none` if the weld was clean, otherwise the defect type. `/app/data/test_features.csv` is a batch we've since had fully inspected but I've held the findings back. `/app/data/README.md` explains the process columns.

Our cell software is Rust, so this has to live there — there's a Cargo project started for you at `/app/predictor` with `smartcore` and `csv` already wired into `Cargo.toml`. Fill in `src/main.rs` so that running it reads both CSVs, fits whatever model you think will hold up, and writes `/app/predictions.csv` with exactly two columns, `weld_id` and `defect` — one row for every `weld_id` in `test_features.csv`, header included, any order. `defect` is your single best call for that weld, spelled exactly as in the training column. The box is offline: the crates already in `Cargo.toml` are cached locally so builds work, but you can't pull in new ones.

About the grading: we delete whatever `predictions.csv` is sitting there, run `cargo run --release` in `/app/predictor` ourselves, and score the file that comes out — so it has to work from a clean build. What matters to us is catching each kind of defect, not the headline hit rate: a cracked weld we wave through is a field failure, and there aren't many of them to begin with. So we score you on the mean of the per-defect-type catch rates, every type counting the same, and that has to reach at least **0.47**. The last model we were shown was right about 90% of the time and still missed most of the cracks, which is why we grade it this way.
